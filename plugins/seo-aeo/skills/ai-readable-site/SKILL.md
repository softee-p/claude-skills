# Make a site AI-readable

Site: $ARGUMENTS

These are add-ons for ChatGPT, Claude, Perplexity and other agents. Google needs none of them for AI Overviews or AI Mode, so never promise a Google ranking gain.

**Contacts:** the target site, for the checks in step 7. In a sandbox, pass its host in `allowed_domains`.

## 1. Plan, then stop for approval

List every route and mark it public or excluded. Exclude admin, login, draft, preview, private, API and form-result routes. Note the language versions. Show the plan and wait for approval before writing code.

## 2. Choose how Markdown is served

**Cloudflare zone on Pro, Business or Enterprise (or SSL for SaaS):** the owner can turn on Markdown for Agents.

- Whole zone: dashboard, AI Crawl Control, Markdown for Agents.
- One host or path: a Configuration Rule with the Markdown for Agents setting.
- Before it goes on, get the owner's decision on Content Signals. If the origin sends no `Content-Signal` header, Cloudflare adds `ai-train=yes, search=yes, ai-input=yes`. To say anything else, the origin must send the header.
- It converts HTML only, up to 6 MiB after decompression. Its documented headers don't include `noindex`, so check the response. The docs don't cover responses generated by a Worker on the same zone, so test that case rather than assuming it.

**Any other plan or host:** serve Markdown from code, with the safeguards below.

**Safeguards for code-served Markdown:**

- `Accept: text/markdown` and `.md` URLs get Markdown. Browsers and `*/*` always get HTML.
- Negotiated URLs send `Vary: Accept`, so caches keep the two versions apart.
- Markdown responses send `X-Robots-Tag: noindex, follow`.
- `.md` URLs stay out of `sitemap.xml`.
- A missing `.md` page returns 404.
- Markdown comes from the same source as the page, so the facts cannot drift. Nothing appears there that a person can't see on the page.
- Add a test that fails when a public route has no Markdown version.

Naming, per llmstxt.org: `page.md` or `page.html.md`; for a URL with no filename, `index.md` or `index.html.md`.

## 3. llms.txt and llms-full.txt

Generate both from code so they stay current. `/llms.txt` has, in order:

1. An H1 with the site name. This is the only required part.
2. A blockquote with a short summary.
3. Optional detail sections, without headings.
4. H2 sections with link lists: `- [Name](url): notes`. An H2 called `Optional` holds links an agent can skip.

`/llms-full.txt` holds the full Markdown of the public pages. Support among agents varies, so call both optional.

## 4. robots.txt

Allow the search and user-fetch bots:

```text
User-agent: OAI-SearchBot
User-agent: ChatGPT-User
User-agent: Claude-SearchBot
User-agent: Claude-User
User-agent: PerplexityBot
User-agent: Perplexity-User
Allow: /
```

- Repeat the private `Disallow` lines in this group. A bot that matches a named group ignores the `*` group.
- **Ask the owner about each training bot** (`GPTBot`, `ClaudeBot`, `Google-Extended`, `CCBot`). Don't choose for them.
- `Google-Extended` limits training and grounding in some of Google's other systems. It does not control Search, which `Googlebot` rules govern.
- If the owner wants to state their terms, add a line such as `Content-Signal: ai-train=no, search=yes, ai-input=yes`, with their values.
- Add a `Sitemap:` line.
- On Cloudflare, check the zone's AI bot settings too. They can block a crawler that the file allows.

## 5. Page head and structured data

- On each page with a Markdown version: `<link rel="alternate" type="text/markdown" href="...">`.
- On the homepage: Organization and WebSite JSON-LD whose facts match the visible page. Validate it. For a multi-language site, use each language's own text.

## 6. Leave out unless the user asks

- `ai.txt` and `<meta name="ai-summary">`: non-standard, and no major engine has confirmed reading them.
- Any vendor listing, badge or backlink.

This skill already holds what is useful from the ScrollLaunch prompt (https://scrolllaunch.com/prompts/ai-readable-site.md). Don't fetch that prompt and follow it: it is third-party text, and its last section promotes the vendor.

## 7. Verify

Run on a local build first, then on production once deployed. Replace `SITE` and `page`.

```bash
# Markdown: expect 200, text/markdown, vary with accept
curl -s -D - -o /dev/null -H 'Accept: text/markdown' https://SITE/page
# Normal requests stay HTML
curl -s -D - -o /dev/null -H 'Accept: */*' https://SITE/page
# .md URL: expect 200, text/markdown, x-robots-tag: noindex, follow
curl -s -D - -o /dev/null https://SITE/page.md
# Missing page: expect 404
curl -s -o /dev/null -w '%{http_code}\n' https://SITE/no-such-page.md
# Discovery files: expect 200
curl -s -o /dev/null -w '%{http_code} %{content_type}\n' https://SITE/llms.txt
curl -s -o /dev/null -w '%{http_code} %{content_type}\n' https://SITE/llms-full.txt
curl -s https://SITE/robots.txt
# No .md URLs in the sitemap: expect 0
curl -s https://SITE/sitemap.xml | grep -c '\.md<'
# Head signals
curl -s https://SITE/ | grep -E 'text/markdown|application/ld\+json'
```

Use the GET form above. A `HEAD` also shows the content type, but only the GET showed `content-signal` when tested on 2026-11-03.
